# 37.6.0 candidate: Enrollment funnel

- Families apply for a seat from their parent account and follow each step:
  inquiry, application, documents, review, offer, accept, enrolled.
- Principals (own school) and superintendents (all schools) get a pipeline
  board with new-student seats per year and grade, a waitlist with positions,
  document review, and **Enroll**. Enrolling creates the student and links the
  guardian.
- The status machine is enforced in the API and by a PostgreSQL trigger. RLS
  covers all four tables, and the history is append-only.
- Documents (PDF/PNG/JPEG, 2 MB max, magic bytes checked) are deleted after
  the decision on a retention schedule. The FERPA purge covers enrollment data.
- Migration `059_enrollment_funnel.sql` (renumber if 051-057 land first).
- New settings: `ENROLLMENT_RATE_LIMIT_PER_MIN`,
  `RETENTION_ENROLLMENT_DOCUMENT_DAYS`, `RETENTION_ENROLLMENT_CLOSED_DAYS`.
- `src/retention.js` now calls every `eduos_retention_feature_*(jsonb)`.
- Flutter screens are not included and remain a follow-up.
- Tests: `test/enrollment-37.6.test.js`, `test/integration/enrollment.test.js`.
- See `docs/ENROLLMENT.md`.
