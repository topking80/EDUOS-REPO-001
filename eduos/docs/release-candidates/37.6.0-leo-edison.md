# 37.6.0 candidate: Leo lesson drafts and Edison trends

- Leo (`leo_lesson`, off by default): lesson drafts built only from the
  course's standards, approved lessons and approved primary sources, through
  the staff AI gateway. Saved as a draft lesson with provenance; the database
  refuses to publish it until a school leader approves it.
- Edison (`/api/edison/trends`, and the `ops_trends` brief, off by default):
  attendance, transport and enrollment trends computed only from EDEN
  aggregation-gate output (minimum cell size 5, complementary suppression).
  The AI brief sees school labels and released counts only.
- `/api/ai/run` logic moved into `src/ai/invoke.js` and shared, including #48's
  district external-provider switch: with an external provider configured, Leo
  and Edison send nothing until the superintendent turns it on (403
  `ai_external_provider_disabled`).
- Migration `059_leo_edison.sql` (after #48's 058; stacked on #48): widens the AI use-case checks (order-independent),
  adds `lessons.generated_by/generated_from` and the publish guard, adds the
  Edison source functions. Grants in `db/runtime_grants.template.sql`.
- No new settings. No student data is an input to either.
- Tests: `test/leo-edison-37.6.test.js`, `test/integration/leo-edison.test.js`.
  See `docs/LEO-EDISON.md`.
